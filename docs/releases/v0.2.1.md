# discogs_player v0.2.1

## Summary

- Release type: `stable`
- Tag: `v0.2.1`
- Date: `2026-05-14`
- Scope: cross-platform installer refresh for the recent collector experience, readiness, onboarding, and GTK cover-art fixes.

## Highlights

- Adds a daily collector insights entrypoint with `dplayer insights`, including setup state, hidden gems, collection health, and value refresh backlog context.
- Improves provider readiness messaging across CLI, diagnostics, API status, web home, and GTK onboarding surfaces.
- Polishes the web dashboard with collector insights and clearer optional-provider degraded-mode guidance.
- Polishes the GTK collector experience, including first-run setup handling and cover-art compatibility recovery for GTK-incompatible cached image formats.
- Adds friend-trial docs and checklist guidance for first public users.

## Known Limitations

- macOS builds are currently unsigned and may require a one-time Gatekeeper quarantine removal.
- Windows builds may show SmartScreen warnings until signing is added.
- Optional playback providers remain optional; Discogs collection, value, wantlist, and discovery workflows work without Spotify configured.
- The Tauri Linux `.deb` and AppImage remain alternate Linux desktop paths; Debian/Ubuntu users should start with the GTK `.deb`.

## Upgrade / Migration Notes

- Breaking changes: none.
- Existing local data and config paths are unchanged.
- Existing cached GTK-incompatible cover files may be replaced by compatible cached artwork during GTK browsing.
