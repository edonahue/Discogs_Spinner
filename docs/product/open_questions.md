# Product Open Questions Backlog

These questions should guide the next product planning pass. They are intentionally non-blocking for current implementation work.

## Experience Priority

1. Should the app optimize first for “what should I play now?” or for deep collection analytics?
2. Which home surface should be primary across web and GTK: quick actions, discovery cards, or status overview?
3. How much opinionated curation is desired vs. neutral data display?

Priority hint for next planning session:

- Decide this section first before roadmap sequencing for the next release train.

## Mobile Direction

1. Should mobile be companion-only (browse + discovery + queue) or full-featured (sync + play handoff)?
2. Should mobile rely on local network connection to desktop, or become a separate product surface later?
3. Which mobile workflows matter most: spin-now, wantlist checks in stores, or value snapshots?

## Paid / Pro Strategy (Future Only)

1. If paid/pro exists, should it be packaged desktop convenience, advanced analytics, or mobile-first?
2. Is paid/pro best as one-time purchase, yearly support tier, or add-on packs?
3. What capability boundary keeps core collector utility free while funding continued maintenance?

## Provider Strategy

1. After Spotify and YouTube scaffolding, which provider(s) matter most next?
2. Should future providers focus on playback control, better matching, or metadata enrichment?
3. How much provider-specific UX should be exposed vs. fully normalized under readiness/capability models?

## Branding and Positioning

1. Should public branding remain “Discogs Spinner” or evolve to a less Discogs-dependent name?
2. Should “spinner” remain central if analytics/discovery grows equally important?
3. What product tagline best matches target users at v1.0?

## Privacy and Data Promises

1. Which local-first/privacy guarantees should be explicit in README and installer UX?
2. Should telemetry remain fully absent by default long-term?
3. What minimum diagnostic data is acceptable to request in support workflows?

## Trial and Launch Operations

1. What is the ideal friend-trial cohort size and platform mix before a broad launch?
2. Which top three friction signals should block a release?
3. Should release artifacts prioritize one native mode (GTK or Tauri) per OS as the default recommendation?

## Suggested Decision Order

1. Experience Priority
2. Privacy and Data Promises
3. Provider Strategy
4. Trial and Launch Operations
5. Mobile and Paid/Pro questions
